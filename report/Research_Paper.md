Nassau Candy Distributor
Factory Reallocation & Shipping Optimization Recommendation System

1. ABSTRACT
This project develops a decision-intelligence prototype for predicting order lead time and evaluating alternative factory assignments for Nassau Candy Distributor. The supplied transactional dataset contains order dates, ship dates, shipping modes, geography, product information, sales, units, gross profit, and cost. Three supervised regression models—Linear Regression, Random Forest Regressor, and Gradient Boosting Regressor—are compared using MAE, RMSE, and R². A scenario-analysis layer then combines predicted lead time with supplied factory coordinates and historical gross-margin information.

2. BUSINESS PROBLEM
The business objective is to identify situations in which a product could potentially be reassigned to another factory to improve shipping efficiency while retaining awareness of profitability. The project is designed as decision support: it provides a transparent what-if comparison rather than automatically executing a factory change.

3. DATASET
The supplied dataset contains 10,194 rows and 18 fields. Variables include order and shipment dates, ship mode, customer geography, division, region, product, sales, units, gross profit, and cost. The target is Lead Time, defined as Ship Date minus Order Date.

4. DATA QUALITY AND CLEANING
The dataset was checked for missing values, exact duplicates, invalid dates, negative lead times, and consistency between Sales, Cost, and Gross Profit. Product names were standardized to remove a known whitespace inconsistency. Gross Profit was also validated against Sales minus Cost.

5. EXPLORATORY DATA ANALYSIS
The observed lead-time distribution contains several concentrated bands rather than a simple normal distribution. These observations were retained rather than deleted automatically because they form systematic patterns in the supplied data. The dataset is also highly imbalanced by division, with Chocolate accounting for most observations and Sugar having relatively few observations. These characteristics are considered when interpreting model performance.

6. FEATURE ENGINEERING
Date fields were transformed into order year, month, day-of-week, and quarter. Profit margin was calculated as Gross Profit divided by Sales. Categorical variables were one-hot encoded. Ship Date was excluded from the predictor set because it directly determines the target and would cause target leakage.

7. MODELING METHODOLOGY
An 80/20 train-test split with random_state=42 is used. The required models are Linear Regression, Random Forest Regressor, and Gradient Boosting Regressor. Performance is assessed with MAE, RMSE, and R². Lower MAE and RMSE indicate smaller prediction errors; higher R² indicates more variance explained by the model.

8. MODEL RESULTS
The completed notebook calculates the final metrics directly from the training/test data and selects the model with the lowest RMSE. In the initial analysis, Random Forest performed better than Linear Regression and Gradient Boosting on the held-out split. Final reported values should be copied from models/model_comparison.csv generated by train_model.py.

9. FACTORY SCENARIO ENGINE
A critical limitation is that the supplied dataset does not include a historical factory-assignment field. Consequently, the machine-learning model cannot learn the causal effect of factory reassignment. To avoid fabricating data, the factory component is implemented as a transparent scenario-analysis layer. The supplied factory coordinates are used with broad regional centroids to calculate a geographic distance proxy. A conservative sensitivity parameter converts relative distance differences into scenario lead-time adjustments. These values are explicitly presented as scenario estimates.

10. PROFITABILITY
Historical gross margin is calculated as Gross Profit divided by Sales. This provides an existing profitability indicator without inventing transportation cost or factory-specific economics. Actual logistics savings cannot be calculated because freight cost is not included in the dataset.

11. RECOMMENDATION LOGIC
The recommendation layer ranks factory scenarios using a user-controlled speed-versus-profit priority. Speed is represented by positive estimated lead-time improvement, while profit context is represented by historical gross margin. A simple risk level reflects the amount of historical support for the selected product/scenario. The recommendation is intentionally explainable and avoids presenting an arbitrary AI score as a business truth.

12. STREAMLIT APPLICATION
The dashboard provides Product, Region, Ship Mode, and Speed-versus-Profit controls. It displays the current factory, predicted baseline lead time, historical margin, scenario risk, factory comparisons, estimated lead-time improvement, and a recommendation. It also explains the assumptions and limitations.

13. LIMITATIONS
The project cannot calculate absolute freight savings, factory capacity utilization, production capacity constraints, or causal factory effects from the supplied dataset. Some product groups have small sample sizes, which reduces confidence in subgroup-specific estimates. The geographic scenario proxy is not a substitute for actual transportation data.

14. FUTURE WORK
Future versions should incorporate historical factory assignments, customer coordinates, factory production capacity, actual freight rates, production processing time, service-level constraints, and real shipment performance. With those inputs, a constrained optimization model could replace the scenario proxy.

15. CONCLUSION
The resulting system demonstrates a complete internship-level analytics pipeline from raw data through predictive modeling and explainable decision support. Its main strength is that assumptions are made explicit rather than hidden: the ML model is used for what the dataset can support, while the factory module is clearly presented as a scenario estimate until richer operational data becomes available.
